# Atlas: Documentation Overhaul (v1)

## Problem

The root README still described "Phase 1" (fixed in an earlier session),
but even after that fix there was no architecture doc, no troubleshooting
guide, no example reports, and no screenshots — everything a repo needs
to be legible to someone encountering it cold (a recruiter, a hackathon
judge, a contributor).

## Architecture

- **`ARCHITECTURE.md`** (new, root): module responsibility table plus a
  Mermaid request-flow diagram, generated by tracing the actual code path
  (`main.py` → `jobs.try_create_job` → `_run_job` → `report_pipeline` →
  each analysis engine → `doc_generator`), not written from memory.
  Cross-references the relevant design docs for anything with a known
  limitation (co-change cap, rate limiter's reverse-proxy caveat) rather
  than re-explaining them and risking drift.
- **`TROUBLESHOOTING.md`** (new, root): one section per failure mode this
  project has actually hit or that follows directly from code that exists
  today (the Python-3.12 pin, `ConfigError` at startup, 429 vs. 429 from
  two different mechanisms, the `.dockerignore` bug from the deployment
  phase, stuck jobs and why they're never silently deleted).
- **`docs/examples/`** (new): two real `POST /documentation` outputs,
  generated live against the running dev server against
  tiangolo/typer (Python, shows a real circular-dependency cluster and
  complexity findings) and expressjs/express (CommonJS, shows route
  detection) — not fabricated or hand-edited.
- **`docs/screenshots/`** (new): real Chromium screenshots (idle, running,
  done-report light/dark) from a Playwright session against the actual
  running dev server, captured for the same phase's frontend-polish work
  — reused here rather than re-captured, since they're already the
  post-fix, accurate state of the UI.
- Root `README.md`: rewritten to link all of the above, embed the
  screenshots in a table layout, and point at FastAPI's auto-generated
  `/docs` (Swagger UI) instead of hand-writing a redundant, driftable API
  reference — confirmed reachable (`GET /docs` and `/openapi.json` both
  return 200) rather than assumed.

## Alternatives considered

- **Hand-written API reference (endpoint list, request/response shapes)**
  — rejected; FastAPI already generates this from the actual Pydantic
  models and route signatures, so it can never drift from the real API
  the way hand-written docs would. Linking to `/docs` is strictly more
  reliable.
- **Recording a GIF** — not done in this pass; the available tooling
  (Playwright) captures static screenshots well but a smooth GIF capture
  would need additional video tooling not verified available in this
  environment. Static before/after screenshots across every view (idle,
  running, done, light, dark, mobile) cover the same "what does this look
  like" need; a GIF is a nice-to-have, not attempted here rather than
  faked.
- **Fabricating example reports** — rejected outright; every example in
  `docs/examples/` is real tool output against a real repo, generated the
  same way a user would get it.

## Validation

`GET /docs` and `GET /openapi.json` both confirmed to return 200 against
the running dev server before linking them. Both example reports
generated live via `curl` against `POST /documentation`, not
hand-authored.
